## Findings

### [M10-WA-001] Graph send uses tenant namespace as Meta template name
- Severity: P0
- Type: WRONG-BEHAVIOR
- Evidence: `WhatsAppMessageService.deliver` sends `namespaceName` `{tenantId}_refill_due`. Meta requires approved unique name `refill_due`.
- User impact: Every patient message fails even with a valid token.
- Fix: Pass `templateUniqueName` to Graph; keep namespace for persistence.
- Suggested tests: Graph body `template.name == "refill_due"`.

**Status:** FIXED 2026-09-15 — `ac_graphTemplateNameIsUniqueName_M10_WA_001`, `graphTemplateNameIsMetaUniqueName_M10_WA_001` — listed Maven still has HEAD residuals (inventory date, expense seed)

### [M10-WA-002] Template variables never sent to Graph
- Severity: P0
- Type: WRONG-BEHAVIOR
- Evidence: `MetaWhatsAppAdapter.sendTemplate` accepts `Map<String,String> variables` then ignores it. No `components`.
- Fix: Map ordered slots to Graph body parameters.
- Suggested tests: Captured Graph JSON includes `customer_name`, `medicine_name`, `pharmacy_name`.

**Status:** FIXED 2026-09-15 — `graphBodySendsOrderedComponents_M10_WA_002`, `orderedSlotsFollowBody_M10_WA_002` — Graph body `components` with named parameters in body slot order

### [M10-ROUTE-001] Staff routing table is never written
- Severity: P1
- Type: MISSING
- Evidence: Production writers of `notification_role_assignment`: **none**. `UserAccessRole` not consulted.
- User impact: Till staff never see slips. Pharmacist-approver can fire with zero recipients.
- Fix: Resolve from `UserAccessRole` + branch, or sync the roster on role assign.

### [M10-ROUTE-002] Five matrix triggers have no production producer
- Severity: P1
- Type: MISSING
- Missing: `ITEM_EXPIRY`, `SUPPLIER_DUE`, `ACCOUNT_CREATED`, `PLAN_LIMIT`, `SUBSCRIPTION_EXPIRY`.
- Fix: Call `route` next to existing limit/expiry/onboarding checks.
