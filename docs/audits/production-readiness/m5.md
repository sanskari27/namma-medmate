## Module production verdict

**M5 should not be called production-ready as a shop-floor procurement desk.** Server PO → GRN → QC → return → stockist khata is real, tenant+branch scoped, idempotent on write keys (`qc:{receiptId}:{lineId}`, `grn:{id}:invoice`, `pr:{key}:{lineId}`), pharmacist QC enforced (`PHARMACIST_REQUIRED`; OWNER also allowed). That is **not** what staff run.

Live Purchases is **New purchase entry → Save & receive goods**: create DRAFT + issue + full GRN in three HTTP calls. No New indent, no version comparison, no Record delivery on ISSUED, no reorder-to-draft, no Pro bulk/spend. QC lives on Inventory; debit notes on Inventory Returns; khata pay on Distributors; sales `/returns` is a different book.

## Findings

### [M5-PO-001] Indent desk unmounted; New indent is gone
- Severity: P1 — UX-vs-CONTRACT / DRIFT
- Fix: Restore indent list as primary; keep bill+GRN as a shortcut that still leaves a visible ISSUED PO.

### [M5-PO-002] Save & receive goods is three non-atomic calls; retry duplicates
- Severity: P1 — STATE-FLOW
- Evidence: `createPurchaseEntry` new UUID per PO **and** GRN. Failure after issue leaves ISSUED PO with no GRN. Retry creates another PO.
- Fix: One server `POST /purchase-orders/receive-bill` with one key; client reuse until success.

### [M5-PO-003] Every bill leaves a forever-open ISSUED PO
- Severity: P1 — STATE-FLOW
- Evidence: Floor never `closePurchaseOrder`. Dashboard `ownerOpenPurchaseOrders` counts DRAFT+ISSUED; `/purchases` lists GRNs not those POs.
- Fix: Close PO when remaining qty is 0.

### [M5-PO-004] ISSUED PO PATCH deletes line IDs that GRNs point at
- Severity: P2 — STATE-FLOW
- Fix: `assertEditable` = DRAFT only; if GRNs exist, 409 `PO_HAS_RECEIPTS`.

### [M5-REO-001] Reorder-to-draft and Pro bulk/analytics have no floor
- Severity: P1 — MISSING
- Fix: Purchases “Draft from this outlet reorder” (Growth+); PLAN_LIMIT → Subscription.

### [M5-REO-002] Reorder rate can take another outlet’s last purchase price
- Severity: P2 — ISOLATION
- **Status:** FIXED 2026-09-17 — fallback last priced batch with `stock_balance` at this `branch_id`.

### [M5-GRN-001] Partial delivery is impossible on the floor
- Severity: P1 — UX-vs-CONTRACT
- Fix: Record delivery against outstanding; qty ≤ remaining.

### [M5-GRN-002] Free qty is blended into unit rate (GST and khata wrong)
- Severity: P1 — WRONG-BEHAVIOR
- Evidence: `unitRatePaise = round((rate×charged) / (charged+free))`. Dialog GST uses charged qty only → dialog ≠ server total.
- Fix: Send charged qty at full PTR; free as zero-rate line or `freeQuantity` that is not taxable.

### [M5-GRN-003] Invoice date and terms stuffed into wrong PO fields
- Severity: P2
- Evidence: `expectedDeliveryDate: draft.invoiceDate`, `paymentTerms: 'CREDIT'`. Khata `dueOn` uses supplier master terms at QC.
- Fix: Persist invoice date on GRN; copy real payment terms.

### [M5-QC-001] Pending pharmacist check is split and unlinked
- Severity: P1 — UX-FRICTION
- Fix: Purchases pending CTA opens Inventory QC with selected id. Hide Accept unless pharmacist/OWNER.

### [M5-QC-002] OWNER may QC; story says pharmacist only
- Severity: P2 — UX-vs-CONTRACT
- Out of scope?: product choice; today’s disconnect is in-scope. Record in DECISIONS or drop OWNER from `requirePharmacist`.

### [M5-QC-003] QC GST totals join PO lines without `branch_id`
- Severity: P3 — ISOLATION
- Fix: `findAllByTenantIdAndBranchIdAndIdIn`.

### [M5-RET-001] Debit note after QC reject is easy to lose
- Severity: P1 — UX-FRICTION
- Fix: Keep outcome + “Open debit note {n}”; Purchases checked bill shows DN.

### [M5-RET-002] Three “returns / distributors / purchases” desks
- Severity: P2
- Fix: Nav Returns → “Sale returns”. Inventory Returns → “Stockist debit notes”.

### [M5-KHATA-001] Growth due reminders never mount; PLAN_LIMIT has no upgrade CTA
- Severity: P1 — MISSING
- Evidence: `listSupplierDues` zero screen callers.

### [M5-KHATA-002] `/suppliers/dues` ages the whole balance on the oldest invoice date
- Severity: P1 — WRONG-BEHAVIOR
- Fix: Reuse `fifoPayables` remaining slices.

### [M5-KHATA-003] Record payment posts without confirming amount vs outstanding
- Severity: P2

### [M5-KHATA-004] Stockist ledger lines are never shown
- Severity: P2

### [M5-SUP-001] Supplier master UI is a short form
