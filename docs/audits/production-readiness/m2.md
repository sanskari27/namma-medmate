## Module production verdict

**M2 should not be called production-ready.** Core onboarding (register, verify, KYC, Free, default branch, D-007 caps, MASTER lifecycle commands, inter-branch transfer locking) is real and tested. Launch-class holes: (1) P0 verify-email URLs → localhost unless SSM is hand-set; (2) P1 floor lock is server-only while SPA still mounts the shop, and subscription EXPIRED does not lock the tenant; (3) P1 D-009 kiosk is a pickup queue on the OWNER cookie, not a safe self-order workflow, and it sniffs `onlineListed` (D-008).

D-007 is correctly implemented. D-008 is correct on the **server** and Subscription rate card; it is wrong on **kiosk catalogue** and Orders chrome.

Register → verify → login; token hashing + TTL; KYC + VA; Free on approve + default branch; lifecycle matrix + MASTER-only status API; `TenantAccessFilter` for non-ACTIVE; D-007 caps; D-008 `ModuleCode.ONLINE_STORE` not entitled; transfers with row+balance locks and concurrent push test; kiosk plan/type gates.

### [M2-KIOSK-001] Self-order does not reserve stock or create a sale
- Severity: P1
- Type: MISSING / WRONG-BEHAVIOR
- Evidence: `KioskService.createTicket` writes ticket only. `normalizeItems` trusts client name/price. No stock check.
- User impact: Oversell; walk-in token with nothing to pick up.
- Fix: Reserve/deduct (or HOLD sale) with server MRP. Do not invent ecommerce (D-008).

### [M2-KIOSK-002] Double-submit creates two tokens
- Severity: P1
- Type: STATE-FLOW
- Evidence: No idempotency key on `POST /kiosk/tickets`.
- Fix: Idempotency key (same pattern as transfers).

### [M2-KIOSK-003] Customer kiosk is the OWNER session; exit PIN defaults to 0000 and is returned by the API
- Severity: P1
- Type: SECURITY
- Evidence: V62 `staff_exit_pin DEFAULT '0000'` plaintext; GET `/kiosk` returns PIN; overlay is a dialog on the same `nmm_access` session; `/pos` still reachable.
- User impact: Full pharmacy session on a public tablet.
- Fix: Hash PIN; never echo; require non-default before `open`; route trap.

### [M2-KIOSK-004] Catalogue prefers `onlineListed`; empty overview fabricates stock
- Severity: P1
- Type: UX-vs-CONTRACT
- Evidence: `catalogueForKiosk` prefers `onlineListed`; empty overview sets `onHandQuantity: 1`.
- Fix: Filter on-hand at session branch only; never prefer `onlineListed`; no fake qty 1.

### [M2-KIOSK-005] Story file never refined after D-009
- Severity: P3
- Type: DRIFT
- Out of scope?: agents must not silently rewrite requirements.
