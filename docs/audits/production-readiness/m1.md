### [M1-AUTH-001] Wrong-app Sign in still creates a session
- Severity: P1
- Type: SECURITY / STATE-FLOW
- Epic/Story: M1-S01 / M1-S10
- Apps: dispensary, admin, server
- Persona: MASTER on a till; OWNER on HQ
- Evidence: SPA `finishSignIn` role-checks **after** `loginWithPassword`; `AuthController.login` already wrote `nmm_access` and may `savedLoginService.bind`. Tests assert UI denied only — no `logoutSession`.
- Expected: Denied app does not keep a live session.
- Actual: Server login succeeds, one-active-session **kills the real HQ/till session**, UI shows denied, cookie stays. If `pinSet`, HQ identity is bound onto the till device.
- Click path: MASTER on `:5174` → opens `:5173` → Sign in with HQ email → “does not match this counter login” → HQ session dead.
- User impact: Accidental URL mix-up signs the operator out of the console they were using and can plant an HQ identity on a shop till.
- Root layer: screen
- Fix: On failed `PHARMACY_ROLES` / `isHqOperator`, call `logoutSession()` and `forgetSavedLogin(userId)`.
- Suggested tests: wrong-app Sign in asserts `logoutSession`; saved-list omits the other-app person.
- Out of scope?: no

**Status:** FIXED 2026-09-15 — `finishSignIn` awaits `logoutSession` + `forgetSavedLogin`; saved picker filters `PHARMACY_ROLES` / `isHqOperator`. `LoginScreen.test.tsx` both apps (22/22). Browser: HQ email on till denied + `/auth/me` 401; OWNER email on HQ denied + `/auth/me` 401. Server still mints then SPA tears down (reject-by-app remains out of scope).
