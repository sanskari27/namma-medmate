## Findings

### [M3-SAFE-001] POS never evaluates, acknowledges, or asserts safety; complete ignores D-011
- Severity: **P0**
- Type: WRONG-BEHAVIOR / SECURITY (clinical)
- Epic/Story: M3-S08 / D-011
- Apps: dispensary + server complete
- Persona: cashier / pharmacist
- Evidence: No production import of `evaluateMedicationSafety` / `acknowledge` / `assertCleared` outside tests. `pos.slice` still nulls `evaluation` with nothing to populate it. `PosCartPanel` save → payment with no Check draft. `SalesInvoiceService.complete` stock + khata + loyalty; **no** `assertCleared`. `PosScreen.test.tsx` still clicks “Check draft” / “Allergy warning”.
- Expected: Warnings before completion; ack with reason; unchecked never shown as safe; cashier may ack; server-authoritative assert.
- Actual: No panel; sale completes; audit never written.
- Click path: Select patient with penicillin allergy → add matching SKU → Charge.
- User impact: Allergic dispense with no review.
- Root layer: screen + complete transaction
- Fix: Restore evaluate on draft lines (hidden until a line exists); ack UI with product names; call `assertCleared` inside `complete`. Do not hard-block; require reason when warnings exist.
- Suggested tests: complete with unmatched keys → 422; allergy path records audit; walk-in with lines is NOT_CHECKED not “safe”.
- Out of scope?: no
