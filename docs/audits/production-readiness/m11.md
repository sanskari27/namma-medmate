## Module production verdict

**Phase 1 M11 is implemented, not launch-clean.** Server Cashfree and Resend boundaries match the story shape: server-priced checkout, HMAC callbacks, `PAYMENT_REQUIRED` on paid `/upgrade`, typed templates, `REQUIRES_NEW`, no secrets in app logs. Production confidence is blocked by **localhost email links (P0)** and **checkout return state that invites a second payment (P1)**, plus **UI/test drift** off the verified “Pay this pharmacy’s plan” slice. HMAC is authentic but not fresh.

## What is solid

Amount/plan server-side (`CheckoutRequest` is planCode + idempotencyKey; extra `amountPaise` ignored). HMAC compare `MessageDigest.isEqual`. SUCCESS early-return + row lock. Paid `/upgrade` → 422 `PAYMENT_REQUIRED`. Blank keys → 422 `PROVIDER_UNAVAILABLE`. Unsigned callback 401. Cross-tenant 404. POS not on Cashfree. Email allowlist PASSWORD_RESET/ONBOARDING/INVOICE_COPY. Cashfree return URL **is** in TF SSM (unlike email URLs).

## Findings

### [M11-MAIL-001] Prod password-reset and verify-email URLs default to localhost
- Severity: P0
- Type: PROD-OPS
- Same fact as `OPS-EMAIL-URL` / `M1-PWD-001` / `M2-REG-001`. Contrast: `CASHFREE_RETURN_URL` **is** seeded.

**Status:** FIXED 2026-09-15 — alias of `OPS-EMAIL-URL`

### [M11-CF-001] HMAC accepts arbitrarily old timestamps
- Severity: P2
- Type: SECURITY
- Evidence: `CashfreeWebhookSignature.valid` / `ResendWebhookSignature.valid` never compare timestamp to `Clock`. FAILED/ABANDONED can still be activated by a later SUCCESS body.
- Fix: Skew window; optionally treat FAILED/ABANDONED as terminal unless `fetchOrder` says PAID.

### [M11-CF-002] Return from Cashfree can look unpaid; owner can checkout twice
- Severity: P1
- Type: STATE-FLOW
- Evidence: PENDING/ABANDONED/FAILED share “Checkout not finished”. `switchPlan` new UUID every click. After return PENDING, board is clickable again.
- Click path: Pay Starter → Cashfree success → land `?payment=` → banner “not finished” → Upgrade again.
- User impact: Double SaaS charge.
- Fix: Distinct PENDING copy; poll; disable CTA while PENDING for that plan; `replaceState` drop query; reuse idempotency while PENDING.

### [M11-CF-003] Checkout copy and tests drifted off the contract
- Severity: P1
- Type: DRIFT / TEST-GAP
- Evidence: Live CTA `Upgrade to ${label}` — no “Pay this pharmacy’s plan”. Tests still click the old string and omit `subscriptionReducer`.
- Fix: Restore pharmacy voice; register slice in tests; focus current-plan heading on SUCCESS.

### [M11-CF-004] Success banner after `?payment=` can be wiped by parallel catalogue load
- Severity: P2
- Type: STATE-FLOW
- Fix: Skip initial load while `payment` present, or do not let fulfilled load clear success.

### [M11-CF-005] Prod env example still sets Cashfree sandbox
- Severity: P2
- Evidence: `.env.prod.example` `CASHFREE_ENV=sandbox` vs TF default `production`.

### [M11-MAIL-002] Resend webhook apply has no pessimistic lock
- Severity: P3
- Type: STATE-FLOW
- Contrast: Cashfree `lockByProviderOrderId`.

**Status:** FIXED 2026-09-18 — alias of `IDEMP-001`.

### [M11-MAIL-003] INVOICE_COPY and ONBOARDING HTML are unescaped
- Severity: P2
- Type: SECURITY
- Evidence: `EmailTemplateRenderer` escapes PASSWORD_RESET only. Pharmacy legal name injected raw into invoice email.
- Fix: Reuse `escape()` on brand, invoice number, URLs.

### [M11-CF-006] Failure banners are not `role="alert"`
- Severity: P2
- Type: UX-FRICTION

### [M11-CF-007] Cashfree `customer_phone` is hardcoded `9999999999`
- Severity: P3
- Type: PROD-OPS
- Fix: Use OWNER phone from `app_user` when present.

**Status:** FIXED 2026-09-18 — OWNER `app_user.phone` (10-digit / 91-prefix); else `9999999999`.
